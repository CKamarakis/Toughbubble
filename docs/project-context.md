# Toughbubble: project context

Living context doc. OpenSpec reads it before every proposal (see `openspec/config.yaml`). Created by the kit on 2026-10-08; it's yours from now on and the kit never edits it.

## Goal

The goal is to create a simple and efficient self tool for self organizing, planning, thinking mapping, etc. For regular people and early stage SMEs. The goal is to be easy, affordable and uncomplicated without losing sofistication. Usability is important. Starts with web but mobile apps possibel in the future and perhaps later MCPs

## Users and needs

It is for regular people that do not need Notion and Miro and whatever with all their features and complexity. Perhaps a more casual everyday tool that offers flexibility without becoming annoying and confusing. Imagine a tool for non tech obssed people. 

## Constraints

A few things to watch out are database size and usage, security, scalability, permissions on tools. 
We need to check if we are being attacked

## Decided

1. The user can create notes freely
2. Each note has an advanced text editor
3. The user can  create projects, folders and notes freely and organize them as she wants for example a project has folder and folders have notes buta note can be inside a project without  an intermediate folder or just stand alone.
4. Storms: these will be like Miro boards. A much lighter version with shapes, texts, greed, sticky notes, fun colors, object layers and grids/tables.
5. Tasks: Not a fully defined idea but basically a Kanban board for tasks but light. 
6. Anyone can sign up and use for free for now. Validation via email.
7. Probabaly we'll need a amrketing site later. 
8. The plan is to be free and donation based up to an x amount of space or usage for teh first year for 1000 users. The rest to eb decided later
9. Images are a topic and a costs so they must be adjusted on the ideal web version fo size and speed at least for the free tier.
10. This is for normal people to make their lives easier no tech bros and teams seaking the next best tool.

## Open questions

1. There are a lot of open questions but we are building in an incremental agile way. Build test move forward
2. Monetization will come later. I plan on starting on a donation based system for the first year and the first 1000 user and I will decide on later how and if I will monetize further
