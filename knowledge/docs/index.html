App branding

Gives ToughBubble a visible identity: where its logo appears in the app, how the logo adapts to the light and dark themes, and which icons browsers and home screens show.

How it works, roughlyEvery logo image is made by one script from the original 1024px files and committed. Nothing is edited by hand. The sidebar loads both the light and dark logo, and the page shows the one that matches the theme.

Archive trash

Lets a user clear items out of their way without losing them: archiving hides finished work, Trash holds items on their way out, and both can be restored, with whole subtrees moving together.

How it works, roughlyWhen you archive or trash an item, everything inside it is marked too, along with which item you acted on. Restore uses that mark to bring the same set back. The Archive and Trash views list only the items you acted on directly. Delete forever removes the item and everything under it in one step.

Note attachments

Note attachments

  1. tables-in-notes · 2026-10-17 — A table pasted into a note collapses into one run-on paragraph, and only bold survives. Why

Pasting tables

tables exist because a pasted table (an FTL / LTL / groupage comparison from a Google result) turned into one run-on paragraph. Pasted widths and spans that are out of range are pulled into range rather than refused, so a paste never produces a note that won't save. tiptap-editor

Editing a table

all commands sit in one toolbar menu. A floating menu would mean more code and focus handling, and right-click is left for the browser's own menu. Delete table was added because without it a table is hard to remove. Header column was added because web tables often use the first column as headers.

What a cell holds

the note's rules themselves keep images, files and nested tables out of cells, so the limit holds when you paste, when you type and on the server. Files added while you're in a table go just below it.

Saving tables

saves stay as strict as for the rest of the note. Dragging a column rounds its width into range in the same step, so dragging can't produce a note that won't save. This was found in code review.

Why

Sidebar tree

your own order is saved to your account, so it is the same on every device. Groups you have never rearranged keep the old "newest first" order, so nothing moved when manual order arrived. fractional-sibling-order

Open items

opening an item expands the folders above it once, then leaves them alone. Before, they were forced open the whole time the item was open, so most projects couldn't be collapsed.

Contents view and sorting

the sort choice is kept in this browser only, so a project page can show "Newest" for a moment after a full reload. "Last edited" ignores archive, trash and restore, because those don't count as edits of the item. per-browser-view-state

Convert between folder and project

Convert moved from the "⋯" menu to the item page, because "Convert to folder" was unclear and looked like it might create a new folder. There's no confirmation, because the change can be undone. The only thing lost is a project's icon and colour, and the hint says so.

Expand and collapse

which folders are open is kept in this browser, not your account. Clicking a project's name also expands it, because people took a name that only opened the page for a broken toggle. per-browser-view-state

Title search

search filters the tree that is already loaded, so it needs no trip to the server. Results show inside collapsed folders without changing what you had open. whole-tree-in-memory

Move items with Move to

dragging no longer moves items into other folders, so a drag always means "reorder". "Move to…" is the only way to move an item, and it also works with the keyboard alone. Keyboard dragging was left out because it would add an extra Tab stop on every row. dnd-kit-tree-drag

Reorder items

you can only reorder within the same folder and the same kind of item. Each reorder saves the order of the whole group again. If two tabs reorder the same group, the last one wins and nothing breaks. If the group changed in the meantime, the save is refused and the tree refreshes. fractional-sibling-order

Small-screen sidebar

a design review found that the phone sidebar couldn't be closed with Escape and didn't move focus into itself. It now uses a ready-made dialog, which handles focus, Escape and blocking the page behind it, instead of custom code that is easy to get subtly wrong.

Touch-friendly rows

touch never starts a drag. Swipes kept turning into drags, and two hold times on one gesture (one to drag, one for the menu) are hard to discover and unreliable. Touch users lose drag to reorder; the Reorder submenu and "Move to…" do the same job. dnd-kit-tree-drag

Item menu layout

the row menu used to show 11 options at once. "New inside" and "Reorder" became submenus to make it calmer.

Consistent dates

dates appear only once the page has loaded in your browser. The server doesn't know your time zone, and dates it filled in were showing in a different format. The cost is that dates appear a moment after the rest of the page.

Account menu

Settings, theme and Sign out took about a third of the phone sidebar, and they are rarely used. They moved into one account menu so the tree gets more room. The cost is that changing the theme takes one extra tap.

Create from a row

creating an item inside a folder took two taps through a submenu. The cost is that on phones, folder rows have one more button, so their titles have less room.

the copy is placed directly below the original, so the whole group's order is saved again. Without that, in a group you never rearranged, the copy would jump to the top as the newest item. fractional-sibling-order

each attachment is copied as a file of its own, so deleting either note never breaks the other. Duplicating notes was first left out by mistake and added after a test round. Duplicating a note with many attachments can take a few seconds, which was accepted for a single-user app.

Attached files go straight from the browser into a private Supabase Storage bucketapp-wide

In short
- Files sit in one private Supabase Storage bucket, `attachments`, organised by user, then note. - The browser uploads directly, signed in as the user. You only ever see files through links that expire after 1 hour.
Why (evidence)
- Server Actions accept at most 1 MB per request, so files can't go through them. - Uploading as the user keeps the database's per-user access checks on every file action. A server client with the secret key was rejected because it bypasses those checks (see supabase-rls-per-owner). - Storms were planned to reuse the same storage.
