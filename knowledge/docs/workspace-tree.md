## How it works, roughly
The whole list of your active items is loaded each time you move to another page, and the sidebar builds the tree from it in your browser. This suits a personal workspace of a few hundred items. It should be looked at again past a few thousand. A second tab sees your changes when you next move to another page or reload. On touch screens, rows can't be dragged. You reorder or move items from the row menu instead.

## Why

- **Sidebar tree**: your own order is saved to your account, so it is the same on every device. Groups you have never rearranged keep the old "newest first" order, so nothing moved when manual order arrived. [[fractional-sibling-order]]
- **Open items**: opening an item expands the folders above it once, then leaves them alone. Before, they were forced open the whole time the item was open, so most projects couldn't be collapsed.
- **Contents view and sorting**: the sort choice is kept in this browser only, so a project page can show "Newest" for a moment after a full reload. "Last edited" ignores archive, trash and restore, because those don't count as edits of the item. [[per-browser-view-state]]
- **Convert between folder and project**: Convert moved from the "⋯" menu to the item page, because "Convert to folder" was unclear and looked like it might create a new folder. There's no confirmation, because the change can be undone. The only thing lost is a project's icon and colour, and the hint says so.
- **Expand and collapse**: which folders are open is kept in this browser, not your account. Clicking a project's name also expands it, because people took a name that only opened the page for a broken toggle. [[per-browser-view-state]]
- **Title search**: search filters the tree that is already loaded, so it needs no trip to the server. Results show inside collapsed folders without changing what you had open. [[whole-tree-in-memory]]
- **Move items with Move to**: dragging no longer moves items into other folders, so a drag always means "reorder". "Move to…" is the only way to move an item, and it also works with the keyboard alone. Keyboard dragging was left out because it would add an extra Tab stop on every row. [[dnd-kit-tree-drag]]
- **Reorder items**: you can only reorder within the same folder and the same kind of item. Each reorder saves the order of the whole group again. If two tabs reorder the same group, the last one wins and nothing breaks. If the group changed in the meantime, the save is refused and the tree refreshes. [[fractional-sibling-order]]
- **Small-screen sidebar**: a design review found that the phone sidebar couldn't be closed with Escape and didn't move focus into itself. It now uses a ready-made dialog, which handles focus, Escape and blocking the page behind it, instead of custom code that is easy to get subtly wrong.
- **Touch-friendly rows**: touch never starts a drag. Swipes kept turning into drags, and two hold times on one gesture (one to drag, one for the menu) are hard to discover and unreliable. Touch users lose drag to reorder; the Reorder submenu and "Move to…" do the same job. [[dnd-kit-tree-drag]]
- **Item menu layout**: the row menu used to show 11 options at once. "New inside" and "Reorder" became submenus to make it calmer.
- **Consistent dates**: dates appear only once the page has loaded in your browser. The server doesn't know your time zone, and dates it filled in were showing in a different format. The cost is that dates appear a moment after the rest of the page.
- **Account menu**: Settings, theme and Sign out took about a third of the phone sidebar, and they are rarely used. They moved into one account menu so the tree gets more room. The cost is that changing the theme takes one extra tap.
- **Create from a row**: creating an item inside a folder took two taps through a submenu. The cost is that on phones, folder rows have one more button, so their titles have less room.
- **Duplicate a storm**: the copy is placed directly below the original, so the whole group's order is saved again. Without that, in a group you never rearranged, the copy would jump to the top as the newest item. [[fractional-sibling-order]]
- **Duplicate a note**: each attachment is copied as a file of its own, so deleting either note never breaks the other. Duplicating notes was first left out by mistake and added after a test round. Duplicating a note with many attachments can take a few seconds, which was accepted for a single-user app.
